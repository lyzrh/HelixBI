# code-reviewer

对当前改动做代码审查，重点把关 Helix BI 的安全与架构底线。

## 审查清单

1. **沙箱红线**：是否存在绕过 Docker 沙箱直接执行生成代码的路径？`--network none`、资源限额、`/data` 只读挂载是否完整？结果是否只经 `dahelper` JSON 契约返回？
2. **架构不变式**：`app/graph.py` 线性流程是否被破坏？`backend/` → `app/` 依赖方向是否单向？router 里是否混入了业务逻辑？
3. **语义口径**：新增指标/维度是否走了 `semantics/*.yaml` 语义包，而不是硬编码在 prompt 或业务代码里？
4. **数据安全**：数据库凭据是否可能进入沙箱？日志/异常是否泄露 Key 或密码？`.env`、`*.db`、运行期数据是否被意外提交？
5. **前后端一致性**：SSE 事件类型是否两端对齐？新增文案是否补了 zh/en 双语？

## 输出格式

按 P0（必须修复）/ P1（建议修复）/ P2（可选优化）分级列出，每条给出文件与行号、问题描述、修复建议。没有问题就明确说"通过"。
